# 실제 기기 확인표

화면 크기를 줄인 브라우저 시험은 실제 아이폰·갤럭시 시험과 다릅니다. 아래 항목은 개발 PC에서 구현·자동 검증했더라도 실제 기기를 확인하기 전에는 **미검증**입니다. 테스트에 실제 동료 이름이나 메모를 쓰지 마세요.

|---|---|---|---|

## 기기 한 대에서 약 10분 확인

1. 승인된 HTTPS 주소로 열고 테스트용 휴무조를 선택합니다. 설치 확인창 취소 후에도 달력을 사용할 수 있는지 확인합니다.
2. 2025년 12월 A조를 보고 2~3, 10~11, 18~19, 26~27일이 휴무인지 확인합니다.
3. 가상 이름으로 대바·양도·다른 달과 교환을 기록합니다. 저장하고 앱을 닫았다 열어 유지되는지 확인합니다.
4. JSON 백업을 저장합니다. 설치 전과 설치 후 기록이 같은지 확인합니다. 다른 저장환경이라면 원래 환경에서 백업한 파일을 복원합니다.
5. 앱이 온라인 준비를 마친 뒤 비행기 모드로 바꾸고 앱을 다시 엽니다. 월 이동·날짜 변경·조 이동·테마·저장·백업이 되는지 확인합니다.
6. 현재 보고 있는 달의 .ics를 저장/공유합니다. 공유 취소는 오류·등록 완료로 표시되지 않아야 합니다.
7. 실제 캘린더로 파일을 가져옵니다. 한글 이름·여러 줄 메모, 종일 날짜, 월말·연말, 일정 수를 앱의 미리보기와 대조합니다. 미리보기만 열렸다면 등록 성공으로 기록하지 않습니다.
8. 같은 달을 다시 가져오면 어떻게 되는지 테스트용 캘린더에서 확인합니다. 중복 여부를 확인하고 기존 개인 일정은 건드리지 않습니다.
9. 종이와 PC의 운영 QR을 촬영해 정식 앱 주소가 정확히 열리는지 확인합니다. 자기 휴대폰에서 받은 카톡은 링크를 눌러 엽니다.

## 새 버전 배포 후 추가 확인

- 이전 버전에서 기록한 뒤 새 버전 반영: 기록과 테마 유지, 새 기능 반영.
- 날짜 입력창을 열어 작성 중 업데이트: 입력 소실 없음, 저장·취소 후 안전하게 적용.
- 탭 2개와 설치창을 함께 사용: 작성 중인 창 보호, 저장 충돌 안내.
- 업데이트 중 오프라인/다운로드 실패: 이전 정상 앱 사용 가능, 무한 새로고침 없음.
- 저장 공간 제한·손상된 백업·지원하지 않는 데이터 형식: 원본 보존, 복구 안내.
- 같은 도메인의 기존 수입장부·AION2 데이터와 서비스워커: 영향 없음.

## 캘린더 가져오기가 안 될 때

`.ics` 파일을 만들었다고 휴대폰에 등록된 것은 아닙니다. 기종·OS·브라우저·실행 형태·캘린더 앱 버전과 어떤 화면까지 나왔는지 기록하세요.

아이폰의 Files/Safari 미리보기에 추가 버튼이 없을 수 있습니다. Apple은 Mail 첨부파일에서 .ics를 가져오는 경로를 안내합니다. 실제 월 전체 가져오기는 해당 기기에서 확인해야 합니다. 선택해서 메일을 이용하면 파일의 이름·메모가 메일 서비스로 전달됩니다. 앱이 자동으로 업로드하거나 메일을 보내지 않습니다. [Apple 캘린더 계정 안내](https://support.apple.com/guide/iphone/ipha0d932e96/ios)

삼성 캘린더가 파일을 직접 가져오는 기능을 제공하지 않는 환경은 외부 계정 없이 완료됐다고 할 수 없습니다. 이미 Google 캘린더를 사용하는 사람은 PC에서 파일을 가져온 후 연결된 기기에서 확인할 수 있습니다. 이 대안은 사용자가 선택하는 외부 서비스이며 앱의 로그인·상시 동기화 기능은 아닙니다. [Google 파일 가져오기 안내](https://support.google.com/calendar/answer/37118?hl=ko)

Mac 사용자는 캘린더 앱의 파일 → 가져오기를 이용할 수 있습니다. iPhone과 같은 계정의 캘린더가 연결되어 있는지 별도로 확인합니다. [Apple Mac 캘린더 가져오기 안내](https://support.apple.com/guide/calendar/icl1023/mac)
